BAGIAN I: PRODUCT REQUIREMENTS DOCUMENT (PRD)

Product Requirements Document (PRD)  Sistem Manajemen Rental PlayStation (Exito Playbox)

1. Ringkasan Produk dan Tujuan

Exito Playbox Management System adalah aplikasi berbasis web menggunakan Python Flask dan SQLite yang dirancang untuk mengotomatisasi pencatatan transaksi sewa konsol, pemantauan status unit secara real-time via polling berkala, dan rekapitulasi laporan pendapatan harian. Tujuan utama produk ini adalah memangkas kesalahan pencatatan manual, mempercepat proses layanan kasir, serta memberikan transparansi finansial bagi pemilik rental.

2. Pengguna dan Peran

  • Kasir / Operator Rental:
  • Memulai dan menghentikan sesi timer sewa konsol.
  • Memilih paket billing dan memproses pembayaran transaksi.
  • Memantau dasbor status ketersediaan unit konsol secara langsung.
  • Pemilik Rental (Owner):
  • Mengakses rekapitulasi laporan pendapatan harian dan bulanan secara langsung melalui layar aplikasi.
  • Meninjau riwayat transaksi penyewaan lengkap dengan pembatasan hak akses (role-based restriction).

3. Fitur per Prioritas (Must & Should Have)

Fitur 1: Pencatatan Transaksi & Timer Sewa (Prioritas: Must)

  • Deskripsi: Sistem mengelola siklus hidup sewa konsol dari mulai hingga selesai secara otomatis.
  • Kriteria Penerimaan (Given-When-Then):
  • Given konsol dalam status Tersedia, When kasir memilih paket jam dan mengklik Mulai Sewa, Then status konsol berubah menjadi Terpakai dan timer durasi berjalan.
  • Given transaksi sewa sedang berjalan, When waktu habis atau penghentian diproses, Then sistem menghitung total biaya sesuai tarif dan membebaskan status konsol.

Fitur 2: Dasbor Monitoring Ketersediaan Unit (Prioritas: Must)

  • Deskripsi: Menampilkan kondisi seluruh unit konsol (PS3, PS4, PS5) dalam tampilan visual yang diperbarui secara berkala (HTTP polling).
  • Kriteria Penerimaan (Given-When-Then):
  • Given pengguna berada di halaman dasbor utama, When halaman dimuat, Then sistem menampilkan seluruh unit konsol beserta indikator warna statusnya (Hijau = Kosong, Merah = Terpakai).

Fitur 3: Rekapitulasi Laporan Pendapatan (Prioritas: Must)

  • Deskripsi: Menyajikan laporan keuangan harian dan bulanan secara otomatis tanpa kalkulasi manual (tampilan langsung di layar tanpa ekspor PDF/Excel untuk rilis awal).
  • Kriteria Penerimaan (Given-When-Then):
  • Given pemilik membuka halaman Laporan, When memilih filter tanggal harian, Then sistem menampilkan total pendapatan, jumlah transaksi, dan ringkasan penyewaan per unit.

Fitur 4: Perhitungan Denda / Kelebihan Waktu Otomatis (Prioritas: Should)

  • Deskripsi: Menghitung biaya tambahan secara otomatis apabila durasi sewa melebihi batas paket (dengan aturan pembulatan kelebihan waktu dihitung pasti per kelipatan 30 menit sesuai kesepakatan klien).
  • Kriteria Penerimaan (Given-When-Then):
  • Given masa sewa telah melewati batas durasi paket, When transaksi dihentikan, Then sistem mendeteksi kelebihan waktu, menerapkan tarif denda proporsional per 30 menit, dan menambahkannya ke total tagihan.

Fitur 5: Validasi Input & Riwayat Transaksi (Prioritas: Should)

  • Deskripsi: Memastikan kelengkapan data masukan kasir dan menyimpan riwayat transaksi secara aman.
  • Kriteria Penerimaan (Given-When-Then):
  • Given kasir membuat transaksi baru, When ada kolom wajib yang kosong lalu disimpan, Then sistem menolak penyimpanan dan menampilkan pesan peringatan validasi.

4. Data Awal (Entitas Utama dan Atribut Penting)

  • Unit Konsol: id_konsol,

ama_unit, jenis_konsol (PS3/PS4/PS5), status_unit (Tersedia/Terpakai/Maintenance).

  • Transaksi: id_transaksi, id_konsol, waktu_mulai, waktu_selesai, durasi, otal_biaya, status_pembayaran.
  • Pengguna / Kasir: id_user,

ama_lengkap, username, password_hash,

ole (Admin/Kasir).

5. Di Luar Lingkup (Won't Have & Could Have)

  • Integrasi Payment Gateway Otomatis (Won't Have): Pembayaran digital otomatis melalui API pihak ketiga ditiadakan; pembayaran dilakukan secara tunai atau transfer manual di tempat.
  • Pelacakan GPS Fisik Konsol (Won't Have): Fitur pelacakan perangkat secara langsung tidak disertakan karena unit dioperasikan di dalam area rental.
  • Ekspor Dokumen Laporan PDF/Excel (Won't Have): Berdasarkan konfirmasi klien, fitur unduh laporan ke format berkas eksternal ditunda dan digantikan dengan tampilan ringkasan langsung di layar aplikasi.

No Topik / Entitas Pertanyaan Konfirmasi (Bahasa Awam) Jawaban & Arahan Klien Implikasi Aturan Basis Data
Q1 Data Pengguna (users) "Kalau ada kasir yang sudah berhenti bekerja, apakah akunnya boleh dihapus dari aplikasi?" Tidak boleh dihapus. Kalau dihapus, laporan transaksi yang pernah dibuat kasir tersebut bisa hilang atau rancu. Cukup dinonaktifkan saja agar tidak bisa login lagi. Tambahkan penanda status aktif (is_active bernilai 1 untuk aktif, 0 untuk nonaktif). Terapkan integritas ON DELETE RESTRICT pada relasi ke transaksi.
Q2 Data Pengguna (users) "Apakah boleh ada lebih dari satu akun Pemilik (Owner) di sistem?" Cukup satu akun Owner. Hanya pemilik utama yang berhak mengubah tarif paket, menambah konsol, dan melihat laporan keuangan penuh. Batasan unik pada username dan penegakan logika bisnis satu akun owner aktif.
Q3 Unit Konsol (consoles) "Apakah jumlah konsol bisa minus? Kalau ada konsol yang rusak total, apakah datanya dihapus?" Konsol adalah fisik nyata, tidak boleh minus. Kalau rusak, jangan dihapus dari daftar karena ada riwayat sewanya; ubah saja statusnya jadi 'maintenance' (perbaikan/rusak). Stok/unit terdaftar sebagai entitas unik (kode_konsol UNIQUE). Unit rusak tidak di-hard delete, melainkan status 'maintenance'. Relasi ON DELETE RESTRICT.
Q4 Unit Konsol (consoles) "Apakah ada jenis konsol selain PS3, PS4, dan PS5 yang disewakan sekarang atau dalam waktu dekat?" Saat ini hanya 3 jenis itu. Belum ada rencana menambah Nintendo Switch atau konsol lain. Batasan CHECK (jenis_konsol IN ('PS3', 'PS4', 'PS5')) dipertahankan dan divalidasi ketat.
Q5 Unit Konsol (consoles) "Apakah satu konsol yang sedang main boleh dipakai oleh pelanggan lain di jam yang sama?" Tidak boleh sama sekali. Satu unit hanya bisa aktif untuk satu sesi sewa sampai sesi tersebut dihentikan/selesai. Validasi sistem: Konsol yang berstatus 'terpakai' tidak dapat dipilih untuk transaksi baru sampai status kembali 'tersedia'.
Q6 Paket Sewa (packages) "Apakah harga paket sewa boleh berbeda antar-pelanggan (misal ada tawar-menawar)?" Tidak boleh berbeda antarpelanggan. Harga sewa wajib seragam dan transparan mengikuti paket resmi agar kasir tidak memanipulasi tarif. Tarif sewa dikunci pada tabel master packages (harga >= 0), kasir memilih paket baku tanpa input bebas nilai rupiah sewa.
Q7 Paket Sewa (packages) "Apakah tarif sewa PS3, PS4, dan PS5 sama, atau berbeda?" Berbeda. Main PS3 paling murah (misal Rp 8.000/jam), PS4 (Rp 12.000/jam), dan PS5 (Rp 20.000/jam). Jadi tiap paket harus jelas untuk jenis konsol apa. Tambahkan atribut jenis_konsol pada tabel packages (CHECK (jenis_konsol IN ('PS3', 'PS4', 'PS5'))) agar paket terikat pada tipe konsol terkait.
Q8 Paket Sewa (packages) "Apakah boleh ada harga paket Rp 0 (gratis)?" Boleh. Terkadang kami adakan promo bonus main 1 jam gratis untuk langganan atau pemenang turnamen rental. Batasan CHECK (harga >= 0) dipertahankan (bukan harga > 0).
Q9 Paket Sewa (packages) "Jika paket promo lama sudah selesai/kedaluwarsa, apakah boleh dihapus?" Jangan dihapus. Kalau dihapus, data nota lama yang pakai paket itu jadi rusak. Cukup disembunyikan/dinonaktifkan agar kasir tidak bisa memilihnya lagi. Tambahkan kolom status aktif paket (is_active INTEGER NOT NULL DEFAULT 1). Transaksi lama tetap mengacu pada package_id tanpa error foreign key.
Q10 Identitas Pelanggan (transactions) "Apakah kasir perlu mencatat nama pelanggan saat mulai sewa, atau sistem rental anonim?" Wajib catat nama panggilan/pelanggan. Saat rental ramai dengan 8 unit menyala bersamaan, kasir sering lupa siapa yang sedang main di TV tertentu. Tambahkan kolom nama_pelanggan TEXT NOT NULL pada tabel transactions.
Q11 Pembatalan Transaksi (transactions) "Bagaimana jika pelanggan baru main 2 menit tiba-tiba mati lampu atau ada kendala mendesak sehingga harus batal main?" Boleh dibatalkan. Asalkan pembatalan dilakukan kasir maksimal 5 menit pertama, transaksi dianggap batal dan tidak dihitung ke omset harian. Tambahkan status pembayaran/transaksi 'batal': CHECK (status_bayar IN ('lunas', 'open_bill', 'batal')).
Q12 Retensi Data (transactions) "Apakah riwayat transaksi lama boleh dihapus setelah beberapa bulan? Berapa lama data harus disimpan?" Tidak boleh dihapus sama sekali (disimpan permanen, minimal 3-5 tahun). Data ini dibutuhkan untuk audit pendapatan tahunan, evaluasi unit paling laris, dan rekap keuangan pemilik. Terapkan kebijakan No Hard Delete untuk data transaksional. Semua relasi ke master menggunakan ON DELETE RESTRICT.
Q13 Denda & Toleransi (fines) "Apakah keterlambatan 1 atau 2 menit langsung kena denda uang?" Tidak langsung denda. Ada toleransi (grace period) 5 menit. Pelanggan butuh waktu menyimpan game (save game) dan mengembalikan stik. Lewat dari 5 menit baru kena denda kelipatan per 15 menit. Logika hitung denda: jika menit_terlambat <= 5, maka biaya_denda = 0. Jika > 5, dihitung proporsional pembulatan 15 menit.
Q14 Denda Toleransi Khusus (fines) "Apakah denda boleh diikhlaskan/dibebaskan (Rp 0) oleh kasir atau pemilik?" Boleh Rp 0. Jika ada kompensasi kendala stik/game macet, denda dapat dihapuskan/dinolkan, namun durasi keterlambatan tetap tercatat untuk arsip. Batasan biaya_denda >= 0 dan menit_terlambat >= 0 dipertahankan.

3.1 Gambaran Umum dan Konteks Pengembangan

3.1.1 Profil Klien dan Karakteristik Bisnis

Exito Playbox merupakan usaha jasa rental konsol permainan PlayStation yang beroperasi di Kota Sampit, Kotawaringin Timur. Tempat usaha ini dikelola langsung oleh pemilik (Owner), Bpk. Hendra, dengan dibantu oleh staf operator kasir. Unit konsol yang disewakan berjumlah 8 unit, terdiri atas 2 unit PlayStation 3 (PS3), 4 unit PlayStation 4 (PS4), dan 2 unit PlayStation 5 (PS5). Setiap unit dilengkapi dengan televisi dan perlengkapan stik nirkabel yang disewakan menggunakan skema paket jam (hourly billing).

3.1.2 Permasalahan Operasional

Berdasarkan hasil elisitasi kebutuhan dan wawancara lapangan pada Minggu 1–3, teridentifikasi sejumlah masalah utama operasional:

  1. Kesalahan Pencatatan Manual: Kasir mencatat jam mulai sewa pada nota kertas. Ketika antrean pelanggan menumpuk di akhir pekan, kasir kerap keliru menghitung selisih waktu sewa dan total tagihan.
  2. Ketiadaan Visibilitas Ketersediaan Unit: Kasir kesulitan memantau unit konsol mana yang kosong atau sedang berjalan tanpa harus memeriksa satu per satu ke setiap ruangan/layar TV.
  3. Perselisihan Denda Keterlambatan (Overtime): Perhitungan denda kelebihan waktu sewa dilakukan secara perkiraan manual tanpa standar toleransi (grace period) yang pasti, sehingga memicu keluhan pelanggan.
  4. Ketiadaan Rekapitulasi Finansial Otomatis: Pemilik harus menghitung ulang seluruh lembaran nota fisik setiap malam untuk mengetahui total omset harian dan performa unit rental terlaris.

    5. 3.1.3 Metode Pengembangan dan Alur Vibe Coding Terkendali

    Pengembangan sistem Exito Playbox menerapkan metodologi Agile Scrum dengan durasi 4 sprint mingguan, mengedepankan pendekatan vibe coding terkendali (Controlled Vibe Coding). Dalam pendekatan ini:

    • Peran Manusia (Analyst & Developer): Memegang kendali mutlak atas pendefinisian aturan bisnis, arsitektur data, verifikasi logika, dan persetujuan kode (Review & Approve).
    • Peran AI: Digunakan sebagai akselerator perancangan draf awal, pembuatan skenario kasus uji (test case), dan pemodelan diagram berdasarkan batasan ketat dokumen PRD dan kamus data.
    • Integritas Versi (Git): Setiap artefak dikelola melalui percabangan fitur Git yang terstruktur (docs-antarmuka, docs-rencana-uji) dengan tinjauan sejawat (pull request) sebelum digabungkan ke cabang utama (main).

    3.3 Pemodelan Sistem Berbasis UML

    3.3.1 Use Case Diagram

    Diagram use case memetakan interaksi antara dua aktor utama: Kasir / Operator dan Pemilik Rental (Owner) terhadap sistem Exito Playbox.

    • Kasir: Berinteraksi dengan UC-01 (Catat Transaksi Sewa), UC-02 (Kelola Penghentian dan Denda), dan UC-03 (Pantau Ketersediaan Unit).
    • Pemilik (Owner): Mengakses seluruh fungsi kasir ditambah hak khusus pada UC-04 (Lihat Laporan Pendapatan) dan UC-05 (Telusuri Riwayat Transaksi).
    • Relasi <>: UC-01 mengikutsertakan UC-03 untuk memastikan konsol berstatus tersedia sebelum sewa dibuka, dan UC-02 mengikutsertakan kalkulasi durasi dari UC-01.

    3.3.2 Skenario Use Case Utama

    • UC-01 (Catat Transaksi Sewa): Kasir memilih unit kosong $\rightarrow$ input nama pelanggan $\rightarrow$ pilih paket durasi $\rightarrow$ sistem memvalidasi kelengkapan $\rightarrow$ status konsol berubah 'terpakai' dan timer mulai berjalan mundur.
    • UC-02 (Kelola Penghentian dan Denda): Kasir memilih transaksi aktif $\rightarrow$ sistem mengevaluasi durasi terpakai terhadap paket $\rightarrow$ jika keterlambatan $> 5$ menit (grace period terlewati), denda dihitung proporsional per 15/30 menit $\rightarrow$ kasir menerima pembayaran $\rightarrow$ unit konsol kembali 'tersedia'.
    • UC-03 (Pantau Dasbor Unit): Dasbor melakukan HTTP polling berkala setiap 10 detik ke server untuk menyajikan warna status unit secara akurat bagi seluruh operator.
    • UC-04 (Lihat Laporan Pendapatan): Pemilik memilih filter periode tanggal $\rightarrow$ sistem mengagregasi total transaksi berstatus 'lunas' $\rightarrow$ layar menampilkan total omset paket, denda, omset bersih, dan kontribusi per unit PlayStation.
    • UC-05 (Telusuri Riwayat Transaksi): Pemilik dan kasir menelusuri data audit transaksi berdasarkan nama pelanggan atau tanggal tertentu dengan paginasi terstruktur.

    3.4 Perancangan Basis Data Relasional

    Basis data diimplementasikan pada SQLite dengan penegakan kunci asing (PRAGMA foreign_keys = ON), terdiri atas 5 entitas ternormalisasi 3NF:

    1. users (id [PK], username [UNIQUE], password_hash, role, is_active).
    2. consoles (id [PK], kode_konsol [UNIQUE], jenis_konsol, status).
    3. packages (id [PK], nama_paket [UNIQUE], jenis_konsol, durasi_menit, harga, is_active).
    4. transactions (id [PK], nama_pelanggan, user_id [FK], console_id [FK], package_id [FK], waktu_mulai, waktu_selesai, status_bayar).
    5. fines (id [PK], transaction_id [FK, UNIQUE], menit_terlambat, biaya_denda).

        4. 4.2 Implementasi Fitur dan Siklus Rekayasa Prompt

        Sistem Exito Playbox dibangun menggunakan Arsitektur Tiga Lapis (Three-Tier Architecture) yang memisahkan lapisan Presentasi (templates/), Lapisan Logika Bisnis (services.py), dan Lapisan Akses Data (models.py).

        Tiga fitur utama yang menjadi tulang punggung sistem adalah:

        1. Fitur F1 — Manajemen Master Konsol (CRUD & Status Inventaris): Mengelola unit konsol fisik dengan validasi ketat kode unik dan jenis konsol (PS3/PS4/PS5).
        2. Fitur F2 — Transaksi Buka Sewa Multi-Tabel Atomik: Membuka sesi sewa kasir dengan memilih unit konsol yang sedang berstatus 'tersedia' dan mengikatnya ke baris transaksi baru secara atomik.
        3. Fitur F3 — Penyelesaian Sewa & Perhitungan Denda Otomatis: Menutup transaksi sewa dengan mengevaluasi durasi penggunaan nyata terhadap durasi paket; bila melewati toleransi 5 menit (grace period), denda Rp 1.000/menit dihitung otomatis dan dicatat ke tabel fines.

          4. Berikut adalah implementasi transaksi atomik pada lapisan layanan data:

          
# services.py: Transaksi atomik pembukaan sewa konsol
def create_transaction(nama_pelanggan, user_id, console_id, package_id):
    # Validasi payload masukan
    is_valid, msg = _validate_transaction_payload(nama_pelanggan, console_id, package_id)
    if not is_valid:
        return False, msg

    with get_db_connection() as conn:
        cursor = conn.cursor()
        # Verifikasi ketersediaan konsol
        cursor.execute("SELECT status FROM consoles WHERE id = ?", (console_id,))
        row = cursor.fetchone()
        if not row or row["status"] != "tersedia":
            return False, "Konsol tidak tersedia untuk disewa."

        # Mutasi dua tabel dalam satu transaksi atomik
        cursor.execute(
            """INSERT INTO transactions (nama_pelanggan, user_id, console_id, package_id, waktu_mulai, status_bayar)
               VALUES (?, ?, ?, ?, CURRENT_TIMESTAMP, 'lunas')""",
            (nama_pelanggan.strip(), user_id, console_id, package_id)
        )
        cursor.execute("UPDATE consoles SET status = 'terpakai' WHERE id = ?", (console_id,))
        conn.commit()
        return True, "Sesi sewa berhasil dibuka."
