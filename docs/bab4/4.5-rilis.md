## 4.5.2 Konfigurasi Deployment Produksi (Waitress WSGI)

Untuk lingkungan produksi, aplikasi tidak dijalankan menggunakan server bawaan Flask (`flask run`) karena bersifat *single-threaded development server* yang rentan terhadap beban konkuren dan serangan DoS. Sistem menggunakan **Waitress WSGI Server** versi 3.0.2 yang terbukti stabil, multi-threaded, dan memiliki jejak memori ringan untuk lingkungan Windows Server maupun Linux host.

Konfigurasi server produksi dikelola secara tersentralisasi pada berkas skrip runner [jalankan.py](file:///c:/Users/maaru/Documents/rpl-project-ps/jalankan.py) dan variabel lingkungan `.env`.

```python
# Cuplikan konfigurasi runner produksi pada jalankan.py
import os
from waitress import serve
from app import create_app

app = create_app()

if __name__ == "__main__":
    host = os.environ.get("FLASK_RUN_HOST", "0.0.0.0")
    port = int(os.environ.get("FLASK_RUN_PORT", 5000))
    threads = int(os.environ.get("WAITRESS_THREADS", 6))
    
    print(f"[*] Exito Playbox Server berjalan pada http://{host}:{port} (Threads: {threads})")
    serve(app, host=host, port=port, threads=threads)
```

Konfigurasi lingkungan produksi diatur melalui berkas `.env` (dengan cetak biru [contoh.env](file:///c:/Users/maaru/Documents/rpl-project-ps/contoh.env)):
- `FLASK_ENV=production` : Mematikan *interactive debugger* dan halaman galat internal demi mencegah *information disclosure*.
- `SECRET_KEY` : Diisi dengan kunci acak kriptografis 64 karakter heksadesimal yang dibangkitkan via `secrets.token_hex(32)`.
- `TOKO_DB` : Menentukan lokasi absolut berkas basis data SQLite `instance/rental_ps.db`.
- `WAITRESS_THREADS=6` : Mengalokasikan 6 thread pekerja worker untuk melayani permintaan kasir dan admin secara konkuren.

## 4.5.3 Prosedur Pencadangan dan Pemulihan Data (*Disaster Recovery*)

Integritas data transaksi rental dilindungi melalui skrip otomatis pencadangan [cadangkan.py](file:///c:/Users/maaru/Documents/rpl-project-ps/cadangkan.py). Skrip ini memanfaatkan antarmuka native `sqlite3.backup` yang melakukan pencadangan *online* tanpa perlu mengunci tabel (*zero-downtime hot backup*).

```python
# Cuplikan mekanisme pencadangan online pada cadangkan.py
import sqlite3
import datetime
import os

def cadangkan_basis_data(db_asal, direktori_tujuan="backups"):
    os.makedirs(direktori_tujuan, exist_ok=True)
    stempel_waktu = datetime.datetime.now().strftime("%Y%m%d_%H%M%S")
    berkas_cadangan = os.path.join(direktori_tujuan, f"rental_ps_backup_{stempel_waktu}.db")
    
    with sqlite3.connect(db_asal) as b_asal:
        with sqlite3.connect(berkas_cadangan) as b_tujuan:
            b_asal.backup(b_tujuan)
            
    print(f"[SUCCESS] Basis data berhasil dicadangkan ke: {berkas_cadangan}")
    return berkas_cadangan
```

Prosedur pemulihan (*restore*) dilakukan dengan langkah:
1. Menghentikan layanan `jalankan.py`.
2. Menyalin berkas cadangan `backups/rental_ps_backup_YYYYMMDD_HHMMSS.db` menimpa berkas `instance/rental_ps.db`.
3. Menjalankan skrip uji cepat `python tests/uji_cepat.py` untuk memvalidasi integritas relasi dan konsistensi skema.
4. Menyalakan kembali layanan `jalankan.py`.
