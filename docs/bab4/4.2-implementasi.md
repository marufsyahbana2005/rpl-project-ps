## 4.2.1 Struktur Proyek Tiga Lapis (3-Tier Architecture)

Basis kode sistem Exito Playbox diorganisasikan secara ketat mengikuti prinsip pemisahan tanggung jawab (*Separation of Concerns* / SoC) ke dalam tiga lapisan:

```text
rpl-project-ps/
├── models.py              # Lapisan 1: Akses Basis Data & Integritas Foreign Key (PRAGMA foreign_keys = ON)
├── services.py            # Lapisan 2: Logika Bisnis, Kueri SQL Berparameter, & Validasi Input
├── app.py                 # Lapisan 3: Controller HTTP, Routing, Middleware CSRF/Rate-Limit, & RBAC
├── templates/             # Antarmuka Presentasi Jinja2 HTML (base.html, login.html, dll.)
├── static/                # Aset Statis CSS responsif dan JavaScript
└── tests/                 # Rangkaian Pengujian Otomatis Pytest & Uji Cepat
```

## 4.2.2 Implementasi Fitur Utama dan Bukti Antarmuka

### 1. Fitur Master Unit Konsol (KF-01)
Mengelola inventaris konsol PlayStation (PS3, PS4, PS5) dengan kode unik minimal 4 karakter. Sistem menampilkan badge status warna: hijau (tersedia), merah (terpakai), dan kuning (maintenance). Penghapusan unit dilindungi integritas referensial foreign key (*RESTRICT*).
*(Rujukan antarmuka: `docs/desain/wireframe/wf-05-kelola-master.png`)*.

### 2. Fitur Transaksi Buka Sewa Atomik (KF-01, KF-02, KF-08)
Kasir mencatat sesi bermain pelanggan dengan memilih konsol berstatus 'tersedia' dan paket sewa aktif. Sistem menjamin atomisitas multi-tabel: pencatatan transaksi sewa dan perubahan status konsol menjadi 'terpakai' terikat dalam satu transaksi basis data tunggal.
*(Rujukan antarmuka: `docs/desain/wireframe/wf-03-buka-sewa.png`)*.

### 3. Fitur Penghentian Sewa & Kalkulasi Denda Otomatis (KF-03, KF-07)
Kasir menyelesaikan sesi sewa pelanggan. Sistem secara otomatis menghitung durasi aktual terhadap paket sewa:
- Bila keterlambatan $\le 5$ menit (masa toleransi), denda tercatat Rp 0.
- Bila keterlambatan $> 5$ menit, denda dihitung Rp 1.000 per menit kelebihan waktu dan otomatis dicatat pada tabel `fines`. Unit konsol langsung pulih berstatus 'tersedia'.
*(Rujukan antarmuka: `docs/desain/wireframe/wf-04-selesai-sewa-denda.png`)*.

## 4.2.3 Cuplikan Kode Representatif Terpilih ($\le 15$ Baris)

### Cuplikan 1: Transaksi Atomik Multi-Tabel Sesi Buka Sewa (`services.py`)
```python
with conn:
    conn.execute(
        "INSERT INTO transactions (nama_pelanggan, console_id, package_id, status_bayar, user_id) VALUES (?, ?, ?, ?, ?);",
        (nama_clean, c_id, p_id, status_bayar_clean, user_id)
    )
    conn.execute(
        "UPDATE consoles SET status = 'terpakai' WHERE id = ?;", (c_id,)
    )
```
*Alasan Arsitektural:* Penggunaan konteks manager `with conn:` pada SQLite menjamin sifat *Atomicity* (ACID): jika query update konsol gagal, pencatatan transaksi di-rollback otomatis sehingga tidak pernah terjadi unit fisik tercatat terpakai tanpa nota transaksi.

### Cuplikan 2: Proteksi Integritas Status Konsol yang Sedang Aktif Disewa (`services.py`)
```python
if current["status"] == "terpakai":
    return False, ["Unit konsol sedang dalam sesi sewa aktif dan statusnya tidak dapat diubah secara manual."], 400
```
*Alasan Arsitektural:* Menutup celah cacat `D-03`. Mencegah anomali bisnis di mana pemilik mengubah status konsol menjadi *maintenance* padahal pelanggan sedang aktif bermain.

## 4.2.4 Tiga Siklus Prompt Representatif dari Jurnal Vibe Coding

### Siklus A: Prompt Kerangka Transaksi Atomik Multi-Tabel (Entri 14 — Status: Terima)
- **Prompt Pengembang:** *"Buat fungsi `create_transaction` pada services.py dengan koneksi SQLite `with conn:` agar insert ke transactions dan update status konsol menjadi 'terpakai' terjadi dalam satu transaksi atomik. Jika unit tidak berstatus 'tersedia', tolak transaksi."*
- **Hasil & Evaluasi:** AI menghasilkan blok transaksi atomik yang rapi dan mematuhi kueri berparameter `?`. Pengujian unit membuktikan ketika dipaksa gagal, database tidak menyimpan data parsial.

### Siklus B: Prompt Hashing Kriptografis Kata Sandi (Entri 29 — Status: Ubah)
- **Prompt Pengembang:** *"Buat mekanisme penyimpanan kata sandi akun pengguna pada SQLite."*
- **Hasil Awal AI:** AI mengusulkan fungsi `hashlib.sha256(password.encode()).hexdigest()` polos tanpa garam (*salt*).
- **Evaluasi & Perubahan Manusia:** Ditolak dan diubah menjadi `werkzeug.security.generate_password_hash(password, method='scrypt')`. Hashing cepat tanpa salt sangat rentan terhadap serangan *Rainbow Table*. Intervensi manusia memastikan kata sandi ter-hash dengan algoritma KDF lambat modern.

### Siklus C: Prompt Normalisasi Tipe Masukan Non-String (Entri 41 — Status: Terima)
- **Prompt Pengembang:** *"Fungsi `_validate_transaction_payload` melempar AttributeError saat `nama_pelanggan` bernilai integer 12345. Perbaiki fungsi agar menormalisasi masukan menggunakan `str(nama_pelanggan)` sebelum operasi `.strip()`."*
- **Hasil & Evaluasi:** AI menerapkan perbaikan minimal dengan mengonversi tipe data secara defensif, meloloskan pengujian regresi cacat `D-01` tanpa efek samping.
